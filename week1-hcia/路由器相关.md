# HCIA - IP路由基础

## 一、核心概念速记（面试口述用）
| 概念 | 一句话定义 | 面试口述话术 |
|------|-----------|-------------|
| 路由表 | 路由器维护的转发路径信息表 | "路由表包含目的网段、协议、优先级、开销、下一跳和出接口，是路由器转发报文的依据。" |
| 路由优先级 | 不同来源路由的优先程度，数值越小越优先 | "直连0最优先，OSPF内部10，静态60，OSPF外部150。优先级决定哪条路由进表。" |
| 度量值/Cost | 同协议内到达目的地的代价 | "优先级相同时比Cost，OSPF看带宽累计，Cost小的进表。" |
| 最长匹配原则 | 逐位比对，掩码最长的条目优先转发 | "路由器收到报文后，匹配路由表中掩码最长的条目，不是看优先级，这是转发层面的规则。" |
| 缺省路由 | 0.0.0.0/0，匹配所有未命中路由 | "缺省路由是最后匹配的路由，一般配在企业出口指向运营商。" |
| 浮动路由 | 通过修改优先级实现的静态路由备份 | "主路由优先级60，备路由配70，主链路故障时备路由自动浮现进表。" |

## 二、华为命令配置模板
### 场景1：配置静态路由（广播接口必须指定下一跳）
```bash
[RTA] ip route-static 20.1.1.0 24 10.0.0.2
# 或同时指定出接口+下一跳（推荐）
[RTA] ip route-static 20.1.1.0 24 GigabitEthernet 0/0/0 10.0.0.2

###场景2：配置缺省路由（企业出口典型配置）
[RTA] ip route-static 0.0.0.0 0 1.2.3.254

###场景3：配置浮动路由（主备链路）
# 主链路，默认优先级60
[RTA] ip route-static 20.0.0.0 30 10.1.1.2
# 备链路，优先级调大
[RTA] ip route-static 20.0.0.0 30 10.1.2.2 preference 70

###场景4：路由汇总 + NULL0防环 [补充]
[RTB] ip route-static 192.168.0.0 22 12.1.1.2
[RTB] ip route-static 192.168.0.0 22 NULL0    # 必须配，防汇总环路

###场景5：查看路由表
<Huawei> display ip routing-table
<Huawei> display ip routing-table protocol static

##四、面试高频题
Q: 路由器如何选择最优路由？
A: 先比优先级(Preference)选最小的进表；优先级相同再比度量值(Cost)。转发时按最长匹配原则查表。
Q: 静态路由的优缺点？适用场景？
A: 优点：配置简单、不耗CPU/带宽。缺点：不自动适应拓扑变化。适用于小型稳定网络或精确控制路径的场景。
Q: 为什么广播接口配静态路由必须指定下一跳？
A: 以太网是多路访问网络，出接口无法确定目标MAC，必须靠下一跳IP解析ARP，否则路由器不知道发给谁。
Q: 等价路由和浮动路由的区别？
A: 等价路由：优先级和Cost都相同，同时进表做负载分担。浮动路由：优先级不同，只有主路由进表，备路由隐藏。
Q: 路由汇总为什么要配NULL0？
A: 汇总路由可能包含实际不存在的网段，流量匹配汇总路由后来回打转形成环路。NULL0接口直接丢弃，避免环路。

##五、易错点/坑
• 通信是双向的：配完A到B的路由，必须配B到A的回程路由，否则ping不通
• 广播接口必须指定下一跳：以太口配静态只写出接口不生效，这是思科华为通用原则
• 最长匹配≠最优路由：最长匹配是转发时的查表规则，优先级/Cost是进表规则，面试常混考
• 浮动路由优先级值：主路由优先级数值要小，备路由数值要大，不要搞反
• 路由递归：如果静态路由下一跳非直连，必须保证路由器有到达下一跳的路由，否则该静态路由不生效
• 精确汇总：汇总范围太广会把不该包含的网段也包进来，造成流量黑洞，尽量算到最长相同前缀
