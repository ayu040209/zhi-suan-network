# HCIA - 广域网技术

## 一、核心概念速记

| 概念 | 一句话定义 |
|------|-----------|-------------|
| WAN | 广域网，连接不同地区局域网的网络，覆盖范围从几十到几千公里 | "面试官你好，广域网是连接不同地理位置局域网的网络，通常通过租用ISP线路或自建专线实现，覆盖范围从几十公里到几千公里。" |
| PPP | 点对点协议，数据链路层协议用于全双工链路上的点到点数据传输 | "PPP是点到点协议，工作在数据链路层，支持认证、多种网络层协议，是串行链路最常用的封装协议。" |
| PAP | 密码认证协议，两次握手明文传输密码 | "PAP是PPP的一种认证方式，两次握手，明文传输密码，安全性较低。" |
| CHAP | 挑战握手认证协议，三次握手加密传输 | "CHAP是PPP的另一种认证方式，三次握手，使用MD5加密传输密码，安全性高于PAP。" |
| PPPoE | 以太网上的PPP协议，将PPP帧封装到以太网帧中 | "PPPoE用于在以太网上承载PPP协议，实现拨号上网的认证和计费，是家庭宽带最常见的接入方式。" |
| CE/PE/P | 用户边缘设备/提供商边缘设备/提供商设备 | "在运营商网络中，CE是用户侧设备，PE是运营商连接用户的边缘设备，P是运营商骨干设备。" |

## 二、华为命令配置模板

### 场景1：PPP基本配置（PAP认证）

```bash
# === 认证方（R1）配置 ===
[R1] aaa
[R1-aaa] local-user huawei password cipher huawei123
[R1-aaa] local-user huawei service-type ppp

[R1] interface Serial 1/0/0
[R1-Serial1/0/0] link-protocol ppp
[R1-Serial1/0/0] ppp authentication-mode pap
[R1-Serial1/0/0] ip address 10.1.1.1 30

# === 被认证方（R2）配置 ===
[R2] interface Serial 1/0/0
[R2-Serial1/0/0] link-protocol ppp
[R2-Serial1/0/0] ppp pap local-user huawei password cipher huawei123
[R2-Serial1/0/0] ip address 10.1.1.2 30

# 验证命令
[R1] display interface Serial 1/0/0
[R1] display ppp peer
```

### 场景3：PPPoE服务端配置（运营商侧） [补充]

```bash
# 步骤1：创建地址池
[Router] ip pool pppoe
[Router-ip-pool-pppoe] network 100.1.1.0 mask 24
[Router-ip-pool-pppoe] gateway-list 100.1.1.1
[Router-ip-pool-pppoe] quit

# 步骤2：创建虚拟模板
[Router] interface Virtual-Template 1
[Router-Virtual-Template1] ppp authentication-mode chap
[Router-Virtual-Template1] remote address pool pppoe
[Router-Virtual-Template1] ip address 100.1.1.1 24
[Router-Virtual-Template1] quit

# 步骤3：绑定到物理接口
[Router] interface GigabitEthernet 0/0/1
[Router-GigabitEthernet0/0/1] pppoe-server bind virtual-template 1

# 验证命令
[Router] display pppoe-server session all
```

### 场景4：PPPoE客户端配置（用户侧） [补充]

```bash
# 步骤1：创建拨号接口
[Router] interface Dialer 1
[Router-Dialer1] link-protocol ppp
[Router-Dialer1] ppp chap user broadband
[Router-Dialer1] ppp chap password cipher 123456
[Router-Dialer1] ip address ppp-negotiate
[Router-Dialer1] dialer user broadband
[Router-Dialer1] dialer bundle 1

# 步骤2：绑定到物理接口
[Router] interface GigabitEthernet 0/0/1
[Router-GigabitEthernet0/0/1] pppoe-client dial-bundle-number 1

# 步骤3：配置默认路由
[Router] ip route-static 0.0.0.0 0 Dialer 1

# 验证命令
[Router] display pppoe-client session all
[Router] display interface Dialer 1
```

## 三、思科-华为迁移对照表

| 思科命令 | 华为命令 | 注意点 |
|----------|----------|--------|
| encapsulation ppp | link-protocol ppp | 华为默认PPP封装，通常不需要改 |
| ppp authentication pap | ppp authentication-mode pap | 语法略有不同 |
| ppp pap sent-username xxx password xxx | ppp pap local-user xxx password xxx | 华为用local-user |
| username xxx password xxx | aaa; local-user xxx password cipher xxx; local-user xxx service-type ppp | 华为必须用AAA且指定service-type |
| ppp chap hostname xxx | ppp chap user xxx | 华为用chap user |
| ppp chap password xxx | ppp chap password cipher xxx | 华为必须指定cipher/simple |
| interface dialer 1 | interface Dialer 1 | 概念相同 |
| pppoe enable | pppoe-server bind virtual-template 1 | 华为需要先生成虚拟模板 |
| ip address negotiated | ip address ppp-negotiate | 华为用ppp-negotiate |
| show interfaces serial 0/0/0 | display interface Serial 0/0/0 | 华为display前缀 |

## 四、面试高频题

**Q: PAP和CHAP认证的区别？为什么CHAP更安全？**

A: PAP两次握手明文传密码，容易被抓包窃取。CHAP三次握手，认证方发送随机数Challenge，被认证方用MD5(随机数+密码)计算后回复，密码不在链路上传输，安全性高。

**Q: PPP链路建立需要经历哪几个阶段？**

A: 三个阶段：LCP协商（链路层参数如MRU、认证方式）-> 认证协商（可选，PAP/CHAP）-> NCP协商（网络层参数如IP地址分配）。

**Q: PPPoE的发现阶段包含哪几个步骤？**

A: 四个步骤：PADI（客户端广播发现）-> PADO（服务器响应）-> PADR（客户端请求）-> PADS（服务器确认并分配Session ID）。

**Q: 为什么广域网链路上常用PPP而不是HDLC？**

A: PPP支持认证、支持多种网络层协议、可扩展性强（能扩展为PPPoE）。HDLC是厂商私有协议，不支持认证，兼容性差。

**Q: CHAP认证中如果两端密码不一致会怎样？**

A: 认证失败，PPP链路会进入Terminate状态。CHAP要求认证方本地存储的用户名密码与被认证方配置的一致。

## 五、易错点/坑

- **坑1：PPP链路IP地址不在同一网段** -- 静态IP地址协商时两端IP必须在同一子网
- **坑2：CHAP认证用户名密码不匹配** -- 被认证方ppp chap user必须与认证方local-user的用户名一致
- **坑3：忘记link-protocol ppp** -- 华为串口默认就是PPP，但如果之前改过封装需要手动改回
- **坑4：PPPoE客户端没有配置dialer bundle** -- 必须先创建dialer bundle再绑定到物理接口
- **坑5：PPP认证缺少service-type ppp** -- 创建local-user时必须指定service-type为ppp，否则认证失败
