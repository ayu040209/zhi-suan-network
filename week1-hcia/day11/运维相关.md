# HCIA - 网络管理与运维

## 一、核心概念速记（面试口述用）

| 概念 | 一句话定义 | 面试口述话术 |
|------|-----------|-------------|
| SNMP | 简单网络管理协议，用于集中管理网络设备的标准协议 | "面试官你好，SNMP是简单网络管理协议，通过NMS网络管理工作站统一管理网络设备，支持查询、配置和告警接收，是网络运维最常用的协议。" |
| NMS | 网络管理工作站，运行网管软件的管理中心 | "NMS是SNMP架构中的管理者，通过Get/Set操作查询和配置被管理设备，接收设备主动上报的Trap告警。" |
| MIB | 管理信息库，定义被管理设备上可访问变量的数据库 | "MIB是管理信息库，以树形结构组织，每个管理对象都有唯一的OID标识符，定义了设备的可管理属性。" |
| Trap/Inform | 设备主动向NMS发送的告警通知 | "Trap是设备主动发送的告警，不需要确认；Inform也需要NMS确认接收，可靠性更高但开销更大。" |
| NETCONF | 基于XML的网络配置协议，提供标准化的设备管理接口 | "NETCONF是新一代网络配置协议，使用XML格式和YANG数据模型，支持配置下发、查询和事务回滚，比SNMP更适合自动化运维。" |
| YANG | 数据建模语言，用于定义NETCONF的数据结构 | "YANG是一种数据建模语言，用来描述NETCONF操作的配置和状态数据的层次化结构，实现数据标准化。" |

## 二、华为命令配置模板（直接复制粘贴）

### 场景1：SNMPv3完整配置

```bash
# 步骤1：使能SNMP代理
[R1] snmp-agent

# 步骤2：配置SNMP版本
[R1] snmp-agent sys-info version v3

# 步骤3：创建MIB视图
[R1] snmp-agent mib-view View_All include iso

# 步骤4：创建SNMP组
[R1] snmp-agent group v3 admin-group privacy read-view View_All write-view View_All

# 步骤5：创建SNMP用户
[R1] snmp-agent usm-user v3 admin admin-group authentication-mode sha Admin@123 privacy-mode aes128 Admin@123

# 步骤6：配置Trap目标主机
[R1] snmp-agent target-host trap-paramsname param1 v3 securityname admin privacy
[R1] snmp-agent target-host trap-hostname NMS address 192.168.1.10 trap-paramsname param1

# 步骤7：配置Trap源接口并开启告警
[R1] snmp-agent trap source GigabitEthernet 0/0/1
[R1] snmp-agent trap enable

# 验证命令
[R1] display snmp-agent sys-info
[R1] display snmp-agent group
[R1] display snmp-agent usm-user
[R1] display snmp-agent target-host
```

### 场景2：SNMPv2c简易配置 [补充]

```bash
# 步骤1：使能SNMP
[Router] snmp-agent

# 步骤2：配置版本和团体名
[Router] snmp-agent sys-info version v2c
[Router] snmp-agent community read public
[Router] snmp-agent community write private

# 步骤3：配置Trap
[Router] snmp-agent target-host trap-address udp-domain 192.168.1.10 paramsname public v2c securityname public

# 验证命令
[Router] display snmp-agent community
[Router] display snmp-agent target-host
```

## 三、思科-华为迁移对照表

| 思科命令 | 华为命令 | 注意点 |
|----------|----------|--------|
| snmp-server community public RO | snmp-agent community read public | 语法类似，华为用snmp-agent前缀 |
| snmp-server host 192.168.1.1 version 2c public | snmp-agent target-host trap-address udp-domain 192.168.1.1 paramsname public v2c securityname public | 华为配置更复杂但功能更灵活 |
| snmp-server enable traps | snmp-agent trap enable | 功能相同 |
| snmp-server group GROUP v3 priv | snmp-agent group v3 GROUP privacy | 华为用privacy，思科用priv |
| snmp-server user USER GROUP v3 auth sha PASS priv aes128 PASS | snmp-agent usm-user v3 USER GROUP authentication-mode sha PASS privacy-mode aes128 PASS | 华为分authentication-mode和privacy-mode |
| show snmp community | display snmp-agent community | 华为display前缀 |

## 四、面试高频题

**Q: SNMPv1/v2c/v3三个版本的主要区别？**

A: v1使用团体名明文认证，安全性差，操作类型少。v2c兼容v1，新增GetBulk和Inform操作，支持更多数据类型，但安全性未改善。v3增加了USM认证加密和VACM访问控制，支持MD5/SHA认证和AES/DES加密，安全性大幅提升。

**Q: MIB的作用？OID是什么？**

A: MIB是管理信息库，以树形结构定义了设备上所有可管理对象的属性。OID是对象标识符，用点分数字表示在MIB树中的唯一路径（如1.3.6.1.2.1.1.1表示系统描述）。

**Q: NETCONF相比SNMP有什么优势？**

A: NETCONF使用XML标准化数据格式，基于YANG模型实现数据结构标准化；支持事务性操作（可试运行和回滚）；基于SSH/TLS安全传输；是机机接口，更适合自动化和SDN场景。

**Q: Telemetry相比SNMP有什么优势？**

A: SNMP采用拉模式（Pull），NMS轮询设备，精度分钟级，开销大。Telemetry采用推模式（Push），设备主动上报，精度可达亚秒级，效率更高，适合大规模网络监控。

## 五、易错点/坑

- **坑1：SNMP团体名大小写敏感** -- 配置和网管侧填写的团体名必须完全一致
- **坑2：Trap源接口没配IP** -- snmp-agent trap source指定的接口必须已配置IP地址
- **坑3：SNMPv3用户组权限不匹配** -- 创建用户时引用的group必须先存在，且权限配置正确
- **坑4：防火墙阻挡SNMP端口** -- UDP 161（SNMP）和162（Trap）需要放通
- **坑5：MIB视图权限不够** -- 只读视图不能用于写操作，配置时read-view和write-view要分开
